# DashLink 1.4.0 Feature Design

Date: 2026-10-24
Status: Approved design, pending implementation plan

## Release scope

1.4.0 ships four items:

1. **Group-picker fix** (issue #6): remove the hardcoded `limit: 20` in the OCS group search call so instances with many groups see the full list.
2. **Unified search provider**: DashLink links appear in Nextcloud's global search.
3. **Dead-link health check**: a daily background job records each link's reachability; admins see a status badge.
4. **Admin-suggested links**: admins publish a catalog of suggested links that users can adopt into their personal links (copy-on-adopt).

Deferred to a later release: widget categories/sections (headliner candidate for 1.5.0).

## 1. Unified search provider

- New class `lib/Search/LinkSearchProvider.php` implementing `OCP\Search\IProvider`, registered in `AppInfo\Application`.
- Matches the query against title, description, and URL of:
  - admin links visible to the searching user's groups (reusing `LinkService`'s existing group-visibility filtering — search must never surface a group-restricted link to a non-member), and
  - the user's own personal links.
- Disabled links are excluded. Suggestions (`is_suggestion = 1`, see §3) are excluded.
- Result entries show the link's icon (fallback to app icon) and open the external URL, respecting the link's `target`.
- No new schema, no settings.
- On any internal error the provider returns empty results rather than breaking global search.

## 2. Dead-link health check

### Background job
- `lib/BackgroundJob/LinkHealthCheckJob.php`, a `TimedJob` with a 24h interval, registered in `Application` and installed via migration/`info.xml`.
- For every enabled link (admin and personal): HEAD request via `IClientService` (GET fallback on 405), ~5s timeout, redirect cap (e.g. 5).
- Per-link try/catch so one failure never aborts the job; failures logged at debug level.

### Status model
Three new columns on `dashlink_links`:
- `health_status`: `ok` | `redirect` | `broken` | `unknown` (default `unknown`)
- `health_checked_at`: datetime, nullable
- `health_detail`: short string (HTTP status code or error class), nullable

Mapping: 2xx → `ok`; 3xx final → `redirect`; 4xx/5xx → `broken`; timeout / DNS / connection error → `unknown` (deliberately distinct from `broken`: the Nextcloud server may simply be unable to reach intranet-only URLs — we must not cry wolf).

### UI
- Admin panel: status badge per link with last-checked time in a tooltip, plus a per-link "Check now" button hitting a new admin endpoint that re-checks immediately.
- Personal settings: same badge (read-only, no "check now") for the user's own links.
- **No dashboard behavior change** — badge only. Broken links are never auto-hidden.
- Export/import ignores the health columns.

## 3. Admin-suggested links

### Data model
- New boolean column `is_suggestion` (default 0) on `dashlink_links`. Suggestions are admin rows (`user_id = null`, `is_suggestion = 1`) and never render on the dashboard directly.
- Group visibility applies: a suggestion restricted to group X is only offered to members of X.
- Adopted copies store the source suggestion id in a new nullable `suggested_from` column, used for "Added" state and duplicate prevention.

### Admin UI
- Per-link toggle "Suggest instead of show" in the existing admin panel, plus a filter to view suggestions — one list, reusing existing CRUD/reorder/duplicate/icon machinery. No separate tab.

### User UI & adopt flow
- Personal → DashLink gains a "Suggested by your admin" section listing visible suggestions with an **Add** button.
- Adopting copies title, URL, description, target, and the icon file into a new personal link. Later admin edits to the suggestion do not propagate (copy-on-adopt).
- The copy counts toward the user's personal-link limit; limit and the global personal-links toggle are enforced server-side (403/422 on violation).
- Already-adopted suggestions show as "Added"; deleting the personal copy allows re-adding.
- Icon copy failure still creates the link, just without an icon.

### Gating
The entire feature (admin toggle and user section) only appears when personal links are globally enabled, since adoption lands in personal links.

## Migrations

One migration adds `health_status`, `health_checked_at`, `health_detail`, `is_suggestion`, `suggested_from` — all defaulted/nullable so existing rows are untouched. Pre-1.4.0 JSON exports import unchanged.

## Testing

PHPUnit coverage:
- Search provider: group filtering, personal-link scoping, disabled-link and suggestion exclusion, empty-on-error.
- Health-check job: status mapping (2xx/3xx/4xx/timeout), per-link failure isolation.
- Adopt endpoint: limit enforcement, duplicate detection via `suggested_from`, gating on the personal-links toggle, group-visibility enforcement.

Manual verification on the OrbStack dev instance (https://nextcloud-dev.orb.local).

## Implementation order

Smallest-risk first, each independently shippable:
1. Group-picker fix (issue #6)
2. Search provider
3. Health check
4. Suggested links
